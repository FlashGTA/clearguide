# ClearGuide 공모전용 제품 기준선

## 1. 제품 정의

> 복잡한 공공 웹서비스에서 사용자가 해야 할 다음 행동 하나를 보여주고, 페이지 이동·새로고침·요소 변경이 발생해도 업무를 안전하게 이어가도록 돕는 웹 접근성 에이전트.

ClearGuide는 현재 단계별 가이드 엔진과 Player SDK를 공개하고 있다. 공모전용 최신화에서는 이 기반을 유지하면서, “가이드 표시”를 “공공서비스 업무 완료”로 구체화한다.

## 2. 1차 대상 사용자와 대표 여정

### 대상 사용자

- 온라인 공공서비스 사용에 어려움을 겪는 고령자·초보 사용자
- 민원·복지·예약 업무를 대신 안내해야 하는 가족·복지 담당자
- 사용자의 문의를 줄이고 싶은 공공기관·서비스 운영자

### 대표 여정 선정 기준

첫 데모 여정은 다음 조건을 만족해야 한다.

- 로그인·결제·캡차 없이 반복 재현 가능
- 5~8단계로 업무 전후가 분명함
- 실제 공공서비스 화면 또는 공공서비스와 동일한 상호작용을 가진 fixture로 테스트 가능
- 잘못된 입력, 페이지 이동, 요소 변경 중 하나 이상의 실패 상황을 재현 가능

정부24 전체 민원 발급처럼 인증·개인정보·캡차가 포함된 여정은 제품의 최종 확장 시나리오로 두고, 첫 검증은 통제 가능한 공공서비스형 fixture에서 수행한다.

## 3. 기능 기준선

### P0 — 데모와 안전성

- 목표와 workflow의 명시적 연결
- 현재 단계·전체 진행률·다음 행동 표시
- 단계별 `urlPattern`과 세션 저장
- 새로고침·페이지 이동 후 상태 복구
- selector 미발견 시 재시도·안전한 중단
- 제출·결제·민감정보 입력 단계의 사용자 확인
- 완료·실패·중단 결과 표시
- 키보드 조작, 고대비, 큰 글씨, 쉬운 안내 문장

### P1 — AI 보조

- 자연어 목표를 허용된 workflow 후보로 분류
- DOM·접근성 트리·화면 텍스트를 이용한 현재 단계 추론
- selector 변경 시 후보 요소 재탐색
- 실패 원인 설명과 다음 복구 방법 추천

AI가 임의의 클릭·제출을 직접 결정하는 구조는 1차 범위에서 제외한다. 모델 출력은 후보·추천이며, 위험 행동은 사용자의 확인과 명시된 workflow가 통제한다.

### P2 — 생태계

- Studio: 운영자/전문가용 가이드 제작
- Player SDK: 기관 웹사이트 임베딩
- Guide Template JSON: 기관별 여정 배포 계약
- 성공률·이탈 단계·오류 유형의 비식별 운영 지표

## 4. 공개 레포 최신화 순서

1. Manifest V3 권한·스토어 메타데이터 점검
2. Extension과 Player SDK의 workflow 계약 통일
3. 세션 상태에 `status`, `lastError`, `completedAt`을 추가
4. selector 미발견·페이지 이동·새로고침 회귀 테스트 추가
5. 공공서비스형 fixture와 성공/실패 데모 확보
6. 실제 공공서비스 적용 시 개인정보·로그인·제출 단계의 안전 경계 검증

## 5. 심사 자료에서의 표현

### 권장

“AI가 사용자의 목표와 현재 웹 화면을 해석해 다음 행동을 추천하고, 검증된 workflow와 사용자 확인을 통해 공공서비스 업무를 끝까지 수행하도록 돕는다.”

### 피해야 할 표현

- “모든 웹사이트를 자동으로 처리한다”
- “AI가 민원 제출까지 무조건 자동 완료한다”
- 실제 구현되지 않은 비전 모델·LLM 기능을 현재 기능처럼 설명

ClearGuide 공개 레포는 제품 실행 기반이며, AI 분석 계층은 P1로 단계적으로 추가한다. 제출물에는 현재 동작하는 기능, 데모 fixture, 다음 개발 계획을 분리해서 기재한다.
